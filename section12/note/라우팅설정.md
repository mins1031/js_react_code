# 라우팅 설정

- 라우팅 설정에 이용할 라이브러리는 'React Router'라는 npm에 등록된 라이브러리.
- 굉장히 다양하고 강력한 기능들을 제공해줌

```
라이브러리 추가 명령어
npm i react-router-dom

-> package.json내에 dependency에
"react-router-dom": "^7.18.2"
이러한 설정값이 추가되어 있음
```

## main.jsx 에 설정

```
import { BrowserRouter } from 'react-router-dom'
// 임포트로 설정.

createRoot(document.getElementById('root')).render(
  <BrowserRouter> -> APP 컴포넌트의 부모로 설정.
    <App />
  </BrowserRouter>
)
```

- 위처럼 App컴포의 부모로 설정하게 되면 아래같은 역할을 함
  - 브라우저의 현재 주소를 저장 및 감지
  - 이렇게 감싸면 리액트의 모든 컴포넌트들이 현재 브라우저의 주소를 사용할수도 있고, 변경을 감지할 수도 있다.

- **개발자도구로 컴포넌트들을 확인하면 알수 있지만 Router는 결국 하나의 context임. 즉 최상위 부모에 Router를 두면 Router context의 provider를 모든 컴포넌트가 사용할 수 있는 구조를 가짐.**
  - 그럼 부모 context와 자식 context는 따로 신경쓰면서 봐야할 개념은 아닌건가? 그냥 자연스러운.. 일종의.. 상속관계인건가?

## app.jsx에 경로 설정

```
import './App.css'
import { Routes, Route } from 'react-router-dom' // 페이지 랜더링을 위한 컴포넌트 임포트
import Home from './pages/Home'
import Diary from './pages/Diary'
import New from './pages/New'
import NotFound from './pages/NotFound'

function App() {

  return (
    <>
      <div>안녕하세요오</div>
      <Routes>
        <Route path="/" element={<Home />}/>
        <Route path="/new" element={<New />}/>
        <Route path="/diary" element={<Diary />}/>
        <Route path="*" element={<NotFound />}/>
      </Routes>
    </>
  )
}

export default App
```

- 최종 프로젝트의 화면구조
  1. "/" : 모든 일기를 조회하는 Home 페이지
  2. "/new" : 새로운 일기를 작성하는 new 페이지
  3. "/diary" : 일기를 상세히 조회하는 diary 페이지
  - 그리고 리액트에선 모든 요소가 컴포넌트로 이루어진다고 했기에 페이지도 컴포넌트로 만들어줌.
  - 페이지용 디렉토리를 src-pages로 생성

- 라우팅 동작원리는 <Routes> 내의 <Route> 항목중 현재 브라우저와 동일한 path를 가진 <Route> 의 컴포넌트를 렌더링 대상으로 선택하는듯?
- 만약 존재하지 않는 path로 사용자가 요청한다면 따로 설정하지 않으면 빈 index.html이 응답되므로 따로 notfound 페이지 생성 및 path엔 와일드카드로 처리 해주면 처리가능.

- 주의사항
  1. <Routes> 내에는 <Route> 컴포넌트만 사용 가능하다.
     - 내부에 다른 내용이 있으면 빈화면 노출 및 콘솔에 에러메세지 출력
  2. <Routes> 바깥의 요소는 모든 페이지에 동일하게 적용됨
     - 모든 컴포넌트 페이지에 "안녕하세요오" 출력 확인.
