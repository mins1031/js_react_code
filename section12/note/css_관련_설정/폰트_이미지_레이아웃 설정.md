## 폰트 적용(폰트파일 핸들링)

- 다운받을 이미지, 폰트 파일적용
- 폰트 파일은 public 폴더에 저장후 index.css에 관련 내용 설정.

```
@font-face {
  /* src 경로의 파일을 font-family에 적용한 이름으로 사용할 수 있다 */
  font-family: "NanumPenScript";
  src: url("/NanumPenScript-Regular.ttf");
}

/* 요소의 모든 body 태그에 폰트 적용 */
body * {
  font-family: "NanumPenScript";
}
```

## 이미지 적용(이미지파일 핸들링)

- 이미지는 src/assests 폴더에 저장
- app.jsx에서 import 로 불러서 사용가능.
  - -> import는 src내의 파일만 가능한가?

```
import emotion1 from './assets/emotion1.png'
import emotion2 from './assets/emotion2.png'
import emotion3 from './assets/emotion3.png'
import emotion4 from './assets/emotion4.png'
import emotion5 from './assets/emotion5.png'

...

<dix>
        <img src={emotion1}/>
        <img src={emotion2}/>
        <img src={emotion3}/>
        <img src={emotion4}/>
        <img src={emotion5}/>
      </dix>
```

- 근데 왜 폰트는 public에, 이미지는 src/assests 폴더에 저장할까?
  - 둘다 정적파일 저장하는 역할의 폴더임.
  - 이유는 vite의 이미지 최적화 과정때문임.
  - 최적화가 필요 없다면 이미지 파일들로 public에 저장해도 무관하고 public의 파일을 불러오는 방법은 살짝 다름
  ```
    <div>
        <img src={"/emotion1.png"}/>
    </div>
  ```
- 그럼 어떤 최적화가 될까?
  - 그걸 확인 하려면 리액트 앱을 빌드하고 배포모드로 실행시켜보면 확실히 확인 가능하다고 함.

  ```
  npm run build - 리액트 앱 빌드
  -> 빌드하면 최상단 폴더 바로 아래 dist라는 폴더가 생성됨. 이게 빌드 결과 폴더임.
  npm run preview - 이게 빌드파일로 배포모드로 실행시키는 명령어인듯?
  ```

  - 이제 dev, preview로 실행한 앱을 보면 겉으로는 큰차이가 없지만 개발자도구로 요소를 확인하면 차이가 보임
    - 최적화되지 않은 이미지 파일은 이미지의 주소가 그대로 노출.
    - 최적화된 이미지 파일은 주소가 암호화되어 적용
      - 이걸 Data uri 라고 함. 이미지 같은 외부 데이터를 문자열 형태로 브라우저메모리에 캐싱하기 위해 사용된다고 함. 그래서 자동으로 해당이미지가 브라우저에 캐싱되기에 최적화라고 하는듯
    - 그래서 크게 2가지의 최적화를 해줌
      - 이미지 주소 암호화로 보안강화
      - 이미지파일 브라우저 캐시에 캐싱함으로 약간의 성능개선 가능

    - 그런데 너무 많은 파일들을 브라우저 메모리에 캐싱하는건 또 다른문제가 발생함.
      - 소수의 이미지, 캐싱할만한 건을 assets에, 중요도가 낮거나 요청이 적고, 중요도가 적은건 public에 저장하는게 좋다고함.

- 반복 Import 최적화 - app.jsx의 이미지 Import가 너무 중복되어 보기 불편함 - src/utils에 js파일 하나 만들고 일종의 이미지-임포트-모듈을 만들어줌

```
<!-- 이미지 임포트 모듈 js 파일 -->
  import emotion1 from './../assets/emotion1.png'
  import emotion2 from './../assets/emotion2.png'
  import emotion3 from './../assets/emotion3.png'
  import emotion4 from './../assets/emotion4.png'
  import emotion5 from './../assets/emotion5.png'

export function getEmotionImage(emotionId) {
switch(emotionId) {
case 1: return emotion1;
case 2: return emotion2;
case 3: return emotion3;
case 4: return emotion4;
case 5: return emotion5;
default : return null;
}
}
<!-- export 꼭해줘야 외부에서 접근가능. -->

<!-- App.jsx 개선 -->
import { getEmotionImage } from './util/get-emotion-image'

...


      <div>
        <img src={getEmotionImage(1)}/>
        <img src={getEmotionImage(2)}/>
        <img src={getEmotionImage(3)}/>
        <img src={getEmotionImage(4)}/>
        <img src={getEmotionImage(5)}/>
      </div>


```
